# ANOMALIES.md — отчёт по review.csv (Задача 3)

`review.csv` позиционируется как «свежая выгрузка для той же базы». После загрузки скриптом
(`npm run db:load-reviews`, таблица `review_import`) выяснилось: **это не свежая выгрузка той же базы**.
Ниже — все замеченные аномалии, как они обнаружены и что это значит.

## Итог (короткий отчёт)

| Метрика | Значение |
|---|---|
| Строк в CSV (с заголовком) | 208 |
| Непустых строк данных | 205 |
| Уникальных id | 202 |
| Дублей id внутри CSV | 3 (строки 42/204, 117/205, 7/206) |
| id, совпадающих с базой `companies` | **6 из 202** (3%) |
| Пустых строк-хвостов | 2 |
| Email в данных | 0 (как и в JSON-выгрузке) |

**Вывод**: 97% записей CSV отсутствуют в базе, id-серии другие (`c_001xxx`, `c_9xxxxx` против `c_000xxx`
в JSON). Это либо выгрузка другого региона/сегмента, либо тестовый дамп, либо перепутанный файл.
В `companies` ничего не мержилось — импорт лежит отдельно в `review_import` с флагами проблем.

## Аномалии

### 1. Файл — не «свежая выгрузка той же базы»
- **Что**: только 6 из 202 id встречаются в `companies` (c_000098, c_000246, c_000263, c_000425, c_000769, c_000851). Остальные 196 id (`c_001xxx`, `c_9xxxxx`) в базе отсутствуют.
- **Как обнаружено**: `SELECT count(*) FROM review_import r JOIN companies c ON c.id = r.id` → 6. Плюс сравнение id-серий: JSON содержит `c_000001…c_0009xx`, CSV — `c_001xxx`/`c_9xxxxx`.

### 2. Дубли внутри самого CSV
- **Что**: id `c_001049` (строки 42 и 204), `c_001050` (117 и 205), `c_001075` (7 и 206) повторяются полными дублями.
- **Как обнаружено**: `GROUP BY id HAVING count(*) > 1` в скрипте загрузки.

### 3. Mojibake — битая кодировка (UTF-8 прочитана как CP1251)
- **Что**: строки 113 и 155: `РћРћРћ В«Р—Р°СЂСЏ РўРµС…В»` (должно быть «ООО «Заря Тех»»), город `РњРѕСЃРєРІР°`/`РЎР°РЅРєС‚-РџРµС‚РµСЂР±СѓСЂРі`.
- **Как обнаружено**: сигнатурные редкие кириллические буквы `ћ`, `ў`, `њ` (U+045B, U+045E, U+045A), которых нет в нормальном русском тексте: «ООО» в UTF-8 = `D0 9E D0 9E D0 9E`, при чтении как CP1251 даёт `РћРћРћ`. Вероятная причина: файл перекодирован (UTF-8 → CP1251) без учёта исходной кодировки.

### 4. Рейтинг вне шкалы 1–5 / не число
- **Что**: `c_001122` rating = `-3` (строка 96); `c_001186` rating = `7.2` (строка 197); `c_001010` rating = `"4,5"` (строка 14) — строковое число с запятой.
- **Как обнаружено**: парсинг + проверка диапазона `[1, 5]` в загрузчике; `"4,5"` пойман как нестандартный формат (в JSON рейтинги — числовые).

### 5. Число отзывов некорректное
- **Что**: `c_001116` = `-10` (строка 61); `c_001079` = `45.5` (строка 98); `c_001187` = `много` (строка 200) — слово вместо числа.
- **Как обнаружено**: проверка целочисленности и знака при нормализации.

### 6. Сайты — мусор и плейсхолдеры
- **Что**:
  - `c_001132` = `https://` — пустой домен (строка 50);
  - `c_001064` = `нет сайта` — текст вместо URL (строка 130);
  - `c_001020` = `htp://sintez-service-453.ru` — опечатка в схеме (строка 141);
  - `https://shared-site.ru` висит на двух разных компаниях (c_001135, c_001088) — явный плейсхолдер.
- **Как обнаружено**: regex `^https?://\S+\.\S+$`; одинаковые сайты — `GROUP BY site HAVING count(*) > 1`.
- **Дополнительно (в JSON тоже)**: в `companies` сайты `https://ip-788.ru`, `https://ip-585.ru`, `https://ip-756.ru` закреплены за двумя компаниями каждая — данные выглядят синтетическими/шаблонными.

### 7. Телефоны — буквы и обрезка
- **Что**: `c_001004` = `8 (925) abc-12-34` (строка 28, буквы в номере); `c_001091` = голый `+7` (строка 199).
- **Как обнаружено**: regex `^\+7 \(\d{3}\) \d{3}-\d{2}-\d{2}$`, проверка на латиницу/кириллицу в номере.

### 8. Города — мусор, опечатки, сдвиг колонок
- **Что** (города CSV, отсутствующие в справочнике `cities`):
  - `Moscow` — латиницей (строка 127);
  - `Санкат-Петербург` — опечатка (должно быть «Санкт-Петербург»);
  - `москва` — нижний регистр; `Москва ` — хвостовой пробел;
  - `РњРѕСЃРєРІР°`, `РЎР°РЅРєС‚-РџРµС‚РµСЂР±СѓСЂРі` — mojibake;
  - **`ул. Советская, д. 89, офис 43` — в колонку `city` попал адрес** (строка `c_001015 «Платформа»`: категория = «Пермь», город = адрес, адрес = пусто) — сдвиг колонок на одну позицию влево.
- **Как обнаружено**: `city NOT IN (SELECT name FROM cities)` + визуальная проверка значений (адрес в поле города распознан по паттерну «ул. …»).

### 9. Пустые строки в хвосте файла
- **Что**: 2 строки-«запятые» в конце CSV (`,,,,,,,`).
- **Как обнаружено**: строки, где все поля пустые, отфильтрованы и посчитаны.

### 10. Email в данных отсутствует
- **Что**: ни в JSON (1000 записей), ни в CSV (205 строк) нет ни одного значения с `@`. Критерий ТЗ «реальные, валидные email» на этих данных невыполним — emails никто не выдумывал, в схеме заведена колонка `email` с проверкой на `@` для будущих импортов.
- **Как обнаружено**: сканирование всех строковых полей обеих выгрузок на `@`.

---

## Что это значит для «той же базы»

1. `review.csv` **нельзя** считать свежим срезом базы из Задачи 1: 97% записей — другие компании.
2. Даже внутри себя файл грязный: дубли, mojibake, мусорные значения, сдвиг колонок.
3. Вероятная природа: файл перекодирован, частично редактировался вручную/склейкой, часть строк — тестовые/шаблонные (общие домены сайтов, повторяющиеся id).
4. Решение при загрузке: импорт в отдельную таблицу `review_import` (сырые данные + нормализованные + флаги `issues[]`), отчётом выше; в `companies` ничего не влито.
